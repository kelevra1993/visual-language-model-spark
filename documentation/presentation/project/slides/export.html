DEPLOYMENT

Every export is checked before it is served

  • Writes TorchScript and ONNX, each with its Triton configuration.
  • Checks every format against the PyTorch model.
  • Replaces the served models only once every format matches.
  • One served model name per task.

Goal: the served model gives the same predictions as the PyTorch model scored during training and evaluation, so the scores reported there hold in production.

The point of the check: the scores of the training and of the checkpoint evaluation were measured on the PyTorch model, and they only hold in production if the served model predicts the same thing. vision_training/deployment/export_model.py takes a run, an iteration and trained or averaged weights, and writes the model as TorchScript and ONNX, each with its Triton configuration. Everything is first written to a staging folder, and every format is compared with the PyTorch model on a batch of another size than the traced one, with the tolerances of the task. Only when every format matches are the served models replaced; otherwise the export stops and the served models are left as they were. Each task has one served model name, from image_classifier to frame_selector. The check compares the outputs of one batch; scripts/deployment/evaluate_served_formats.py goes further and scores the whole test split through every served format against the eager model: in the serving benchmark every FP32 path matched within 0.01 points, and FP16 too once the exported NMS of the detector was fixed (next slides).
