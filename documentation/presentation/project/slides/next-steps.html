The serving benchmark of 17 November (three models, every export format, dynamic batching on and off, latency, throughput, memory and the test metric through every served format) leaves its follow-ups: serving defaults (TensorRT FP16, the exported dynamic batching off) and a faster batched NMS for the eager and TorchScript detectors. Two of its findings are fixed since: the exported NMS of the detectors no longer overflows FP16 (its TensorRT FP16 engine within 0.21 points of the eager model), and the ONNX export writes the output frames of the sequence labeller and frame selector dynamic, so that Triton loads them. It also decides on native TensorRT engines built at export and a mounted engine cache; INT8 and FP8 need calibration or quantization nodes first. In parallel, the instance segmentation benchmark continues stage by stage like the detection one: stages 0 to 3 are done, and the image branch of the mask head (stage 3b, design A) raised the test mask mAP to 88.65 %; next come the U-Net skips of design B, then upsampling, a shared mask head, the level chosen by box size, a finer map and mask scoring. Newcomers start with the README, then the reference and workflow documents, then the videos.
