DEPLOYMENT

Every export states how to build its input

  • Written into the ONNX metadata and preprocessing.json.
  • States the BGR photo, the resize, its interpolation, the padding and the layout.
  • The export refuses an input it cannot describe.
  • A test rebuilds the inputs from the contract alone, pixel for pixel.

The three resizes of a 640 x 359 photo for an input of 256. Photo: COCO 2017 validation image 288882, Flickr, CC BY 2.0.

A server that feeds the model does not have to guess the preprocessing: the input contract travels with the model. Every export writes it into the metadata of model.onnx and as preprocessing.json next to both formats: the photo as OpenCV decodes it in BGR, a stretch, keep_ratio or tiles resize with its interpolation, the padding and the layout. If a run uses an input the contract cannot describe, the export stops before writing any file. A test rebuilds the inputs of a photo from the contract alone and checks them pixel for pixel against the training preprocessing.
