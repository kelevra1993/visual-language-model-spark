GETTING STARTED

One YAML file per run, checked before launch

  • Every key explained by its comment.
  • Each task ships an example and a synthetic file.
  • Four sections shared by every task, the rest its own.
  • A wrong file stops the launch, every problem listed at once.
A run is described by one YAML file. Every task has a configuration_example.yaml and a synthetic configuration in vision_training/configurations/<task>/, holding only, and all, the keys the task reads, each explained by its comment. Four sections are shared by every task (ExperimentConfiguration, Optimization, Data, Backbone), the others belong to the task, such as the region proposal and detector sections of detection. The file is checked before anything starts: a missing key, an unusable value, an inconsistent combination or a removed setting stops the program with the list of every problem found, for example a negative learning rate and an image size of 500 that the five poolings of the backbone cannot divide.
